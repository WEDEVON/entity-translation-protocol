# Contributing

## Goals

Contributions should improve one or more of the following:

- clarity of the protocol
- reusability across languages or domains
- reliability of prompt automation
- safety of audit, promotion, and release workflows

## Principles

- keep manual and generated concerns separate
- keep prompts explicit about inputs and outputs
- prefer portable examples over project-specific assumptions
- record ambiguity instead of hiding it
- avoid adding workflow steps that cannot be audited

## Preferred Contribution Types

- protocol refinements
- additional examples
- better templates
- better prompt contracts
- script scaffolds
- repository structure improvements

## Before Opening A Pull Request

- make sure new files fit the existing structure
- keep non-example content in English
- explain why the change improves the protocol
- note any tradeoffs or unresolved questions
